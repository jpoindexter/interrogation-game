# Accuse when the evidence is ready

The follow-up to the real startup/easy generation check exposed an artificial accusation barrier. After three targeted questions, the public transcript contained both the suspect's denial of being in the meeting room between 10:00 and 10:30 and a named witness identifying her there at 10:20. The player submitted that precise contradiction. The server returned HTTP 409 before judgment because only one of two clue markers had unlocked.

[The before-change evidence](evidence/generated-accusation-before.json) records the actual production HTTP replies. The case's private solution was not read to form the questions or accusation. Response times were 18.638, 20.132 and 15.524 seconds. This demonstrates a progression barrier, not a verified win: the rejected request never reached the judge.

## Rule change

Generated-case clue markers remain optional hints. An active interview with attempts remaining accepts a specific accusation for judgment regardless of clue count or stress. The judge and server-owned attempt/outcome rules remain in force; removing the barrier does not award success. The authored evidence practice still requires a contradiction established through the pinned-statement and exhibit workflow.

The controls and help distinguish these two case types. Players should compare words with source evidence, not increase a dramatic stress meter merely to unlock a button.

## Verification boundary

Fifteen focused session/gameplay checks passed after the server change. They include an unsupported accusation consuming an attempt, a correct mocked judgment committing a win with zero clue markers, and the authored evidence workflow. These checks establish the application rule and authored regression boundaries; they do not establish a real provider verdict or browser interaction for the revised rule. The integrated follow-up below exercises the revised rule with the real provider.

## Actual generated-case follow-up

After lint, size and production build passed, the agent CLI generated one startup/easy case in relaxed mode through the running local server. A question based only on the public cover story and named witness returned the witness’s personal identification and time in 22.399 seconds. A precise accusation cited that contradiction while explicitly distinguishing presence from theft. Judgment returned HTTP 200/correct in 18.029 seconds with zero clue markers. The server recorded a win, one used attempt, no ranked token and a saved local completion export.

The CLI then retrieved the result and recovered state in separate processes. The canonical result matched exactly, including score, outcome and the two-step conversation path (neutral dialogue, supported accusation). Public responses omitted private provenance. The private ledger retained execution-time Luna draft, Sol review and Sol suspect prompt hashes. [Full public evidence and source hashes](evidence/generated-cli-playthrough.json).

This establishes one generated case through actual generation, dialogue, judgment, local export and recovery. It does not establish every generated case, browser rendering, voice, hosted persistence or reliable semantic review. The earlier material review failures remain open. No voice credits were used, and no broad model evaluation batch was run.
